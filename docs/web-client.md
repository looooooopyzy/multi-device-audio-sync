# Browser Speaker Client — Phase B

Run `windows-master.exe --source tone` from the repository root. Find the Windows LAN IPv4 with `ipconfig`, allow inbound TCP 17890 in Windows Firewall on the Private profile, and open `http://WINDOWS_IP:17890` on a device on the same Wi-Fi. No internet or domain is used. Use `--source system` instead to capture the default Windows output mix while another application plays audio.

The page connects to `/ws`, sends a persistent browser ID and device name, and replies to four sync requests per second using `performance.now()`. The Windows master calculates RTT, filtered offset, drift, and jitter with its existing `ClockSyncEngine`; the browser displays the returned model. Tap **Enable Speaker** before requesting a click. The button creates/resumes `AudioContext` inside the tap handler, including the iOS Safari user-gesture path.

After at least eight clock samples, tap **Test Sync Click**, or press **c** in the Windows master console. The master schedules one click for QPC time + 1000 ms and sends the identical `CLICK_AT` timestamp to all browsers. The page maps that time to `AudioContext.currentTime` and schedules a 10 ms burst. A click that arrives with less than 15 ms of lead is skipped and counted as late.

**Delay calibration** is per browser and survives reloads in `localStorage`. Positive values delay this speaker, negative values advance it. The range is ±500 ms. Phase B sends 10 ms binary Float32 PCM packets with a presentation time 200 ms after capture. The browser queues packets until they are within 120 ms of presentation, then calls `AudioBufferSourceNode.start(when)` using the same master-to-browser clock model as the click test. The UI reports received packets, buffered plus scheduled audio, and sequence gaps/late blocks. The browser does not play packets immediately on receipt.

Keep browser pages in the foreground and use a trusted LAN. If PCM packet count stays zero, confirm the Master reports a running source, AudioContext is RUNNING, and the source actually produces audio. To synchronize system music, set VB-CABLE as Windows' default output and choose a different physical render endpoint in the GUI; without this routing, system audio is only forwarded to the browser. See [real-time audio](realtime-audio.md). iPad Safari, Android Chrome, and acoustic alignment still require real-device verification.
